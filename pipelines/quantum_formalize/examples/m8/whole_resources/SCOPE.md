The actual three-branch solver is instrumented once: original Euclid; optionally the actual weighted discovery; optionally one actual M6 solve; and a successful original-coordinate undo. A constant-length list stores only executed stage charge totals. No pin-query/access history is stored. The genuine M6 witness counter already includes the initial query, actual pin count, pin maintenance and transformed preprocessing, so it replaces rather than adds to the distance counter on success.

The reusable fixed-cutoff allocation comes from BankLayout's explicit six buffers, named registers and actual M6 storage formula. Setup charges clearing that allocation, reading input bits and caching the fixed cutoff. Primitive array scans, modular arithmetic and inverse computations use the same standard symbolic binary-operation model as the accepted M6 contract, not Lean runtime. Costs include discovery failure and early NoLogical; no small-span premise is imposed on input or rejected branches.

Canonical gates are solver, discovery_resources, actual_optimizer_resources and bank_layout. This draft is not a proof closure. A downstream sequential contract must instantiate actual payload size, actual executed stage charges, binary address tags, in-place projection and the common n^12/n^4 bounds. No full machine-code extraction or M9 claim is added.

The setup also charges a fixed two-block input-validation scan: one coordinate-difference/binary-gcd update and weight/cursor bookkeeping per position. This is a separate connectivityScanWork fold, not hidden inside the cheaper array input-copy charge. Public correctness remains restricted to Valid inputs; no InvalidInput correctness goal is added.
