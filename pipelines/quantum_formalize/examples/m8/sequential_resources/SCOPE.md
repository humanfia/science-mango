The common sequential simulation uses the actual BankLayout.payloadSlots N allocation and binary address size, not a freely supplied memory or cost parameter. TaggedStore.read/write already prove concrete scan semantics and counted cost. Their uniform scan allowance is obtained by substituting this allocation into those bounds; whole-algorithm charges are the actual at-most-six executed segments from WholeResources.run.

The sequential accounting recursively accumulates the validated scan allowance for each indexed-bit upper-charge unit, and separately counts construction of the actual binary-tagged initial allocation by visiting its addresses. This is a compositional upper charge in the same standard symbolic bit-operation model as M6 and DiscoveryResources. It is not an assertion about Lean runtime or a replacement definition equal to the desired n^12 polynomial. Universal quantification over stored Boolean values preserves correctness for every actual intermediate state; the allocation and executed-stage charges themselves are fixed by the concrete M8 algorithm.

Final statements must include actual packed-memory read/write projection, unchanged layout, the whole three-branch result projection, and closed sequential n^12/storage n^4 bounds. No free correctness/evaluator/transversal/allocation oracle and no M9 or gate-level code-extraction requirement is introduced. Canonical gates remain whole_resources, bank_layout and tagged_store.
