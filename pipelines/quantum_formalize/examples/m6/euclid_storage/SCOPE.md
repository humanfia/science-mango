# M6 Euclidean preprocessing storage

This module supplies the independent space bound needed to combine Euclidean preprocessing with the original M6 indexed-array algorithm. It imports the complete accepted21-target Euclid closure only after verifying canonical manifests, receipts, original target/source hashes and portable declarations. The predecessor's cubic time bound is not used as a storage bound.

The actual machine has four polynomial slots: p, q, the working remainder, and saved M. The last slot retains the third input during the first gcd; the second gcd reuses it. remLoop is a tail-recursive accumulator loop overwriting the work slot. gcdLoop runs that inner loop and then tail-calls after replacing p/q with q/remainder and resetting work. It reads all needed values from the returned fixed slot record. The two calls composing preprocess reuse these same slots. Refinement targets identify every output and counter with the already accepted original Euclidean program; no abstract simulator-correctness premise remains in the terminal theorem.

remSafe/gcdSafe recursively check every executed configuration, including inner-loop calls and terminal counters. Their reusable lemmas take remaining-run budgets; preprocess_safe discharges them from the actual accepted Euclidean cancellation, round, pass and output-width bounds. With width=N+1, the two calls together use at most4width cancellations,2width rounds and18width passes, inside the32width register capacity. Fuel and degree/index/shift values also fit this capacity. The array scan and XOR loops have indices bounded by their fixed width.

Four binary arrays faithfully encode the polynomial slots by the accepted dense representation and the new slots_encoding theorem. The concrete allocation reserves sixteen control words for both loops' fuel/counters, degrees, scan indices, shift, phase/carry and addresses. registerBits(width)=width+5 is proved sufficient to encode every value≤32width. actualPreprocessStorage is the sum of this literal layout:4width+16(width+5). A later theorem bounds it by512width². The bound is derived from fixed reusable storage and all-state safety, rather than an arbitrary quadratic budget or the algorithm's running time.

This formalizes the original indexed-array storage model. It does not claim that Lean's persistent polynomial representation or a language interpreter automatically performs the same slot allocation, and imposes no native-code extraction gate.
